# HEALTH PLUS — Product Architecture, AI, Data & Integration Audit

> **Team:** CASA Vital  
> **Product:** HEALTH PLUS (*Observe. Understand. Guide.*)  
> **Audit Date:** 2026-11-11  
> **Audit Methodology:** Direct inspection of source files (`frontend/src/**`, `docs/**`, `vercel.json`, `.env.example`, `.env.local` key names), runtime checks, and compiled output.

---

## Executive Summary & Root Causes Discovered

1. **No Backend Gateway / Live LLM Integration (`Blocked by missing credentials or external integration`)**:
   - The repository contains `frontend/`, `docs/`, and static SPA `vercel.json`. There was no `api/` or backend server folder, and `.env.local` held only `VERCEL_OIDC_TOKEN` (`GEMINI_API_KEY`, `OPENAI_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` are absent).
   - Consequence: Every message in `AiCoachPage.tsx` / `FloatingAiCompanion.tsx` routed solely through local TypeScript rules (`frontend/src/engine/aiOrchestrator.ts`) without a server-side LLM proxy or response validator.

2. **Browser Persistence Without Remote Database (`Partially working` / `Blocked by missing credentials`)**:
   - All profile, meal logs, workout logs, conversation memory, and preferences were stored in `localStorage` (`healthplus_app_state_v2`).
   - Root auth/persistence flaw found in `AppContext.tsx`: `signInOrRegister` merged a new email login onto an existing `prev.profile` instead of scoping saved profiles per email account cleanly or separating sessions cleanly across sign-out/re-sign-in and multi-user testing.
   - Supabase credentials (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `DATABASE_URL`) are not provisioned in the environment, blocking Postgres/Supabase sync.

3. **Conversational AI NLU & Language Continuity Flaws (`Partially working`)**:
   - **Follow-up Language Switching (Scenario C)**: In `aiOrchestrator.ts`, `"Aaj gym nahi ja sakti."` set `detectedLanguage: 'hinglish'`, but replying `"I only have ten minutes."` caused `detectLanguage()` to drop back to `'en'` because zero Hinglish dictionary tokens appeared in that follow-up turn.
   - **Spelled-out Duration Parsing**: `understandMessage()` only matched digits (`5|10|15|... min`) and ignored spelled numbers (`"ten minutes"`, `"five mins"`, `"das minute"`).
   - **Negated Equipment Misclassification**: `"I don't have dumbbells."` matched `/dumbbells/` before checking the negated clause, wrongly classifying `mentionedEquipment: 'dumbbells'` instead of `'none'`.
   - **Dish Rejection Clarification (Scenario B)**: `"Mujhe dinner mein paneer bhurji nahi khani."` jumped straight to alternate recipes without asking *why* first, and calorie/protein remaining questions (`"kitna protein bacha hai?"`) triggered meal cards instead of direct remaining macro math.

4. **Nutrition Dataset Provenance & Computation Gap (`Prototype only`)**:
   - `frontend/src/engine/nutritionCatalog.ts` stores 14 Indian home recipes with manually entered macro totals tagged `prototype_kitchen_estimate`. Full IFCT 2017 CSV / USDA FoodData Central bulk records specified in `docs/DATABASE_SCHEMA.md` have not yet been imported or synced from Postgres.
   - Required correction: Compute recipe macros deterministically from ingredient-level per-100g composition records (`foodComposition.ts`) and keep transparent provenance labels instead of claiming live IFCT 2017 DB lookup.

5. **Voice Companion Capability Boundary (`Partially working` — Browser API only)**:
   - `frontend/src/hooks/useVoiceCompanion.ts` wraps browser `window.SpeechRecognition` / `window.speechSynthesis`. It works in Chromium/Edge desktop when permitted, fails silently or shows fallback errors in unsupported browsers/headless environments, and lacked voice selection, speech speed controls, microphone permission state checks, and a provider abstraction for cloud neural STT/TTS.

6. **Exercise Pose Vision Contract (`Prototype only` + Preserved Integration Contract)**:
   - `MoveStudioPage.tsx` integrates a genuine 3D articulated Three.js model (`KinematicHuman3D.tsx`) and optional private on-device `<video>` camera mirror, while keeping `frontend/src/types/exerciseIntegration.ts` (`ExerciseLiveEvent`, `ExerciseSessionSummary`, `ExerciseStudioProps`) untouched per `docs/EXERCISE_INTEGRATION.md`.
   - Automated computer-vision rep counting from the teammate pose model is not yet plugged into `MoveStudioPage`; users log reps via manual step controls / timed sessions (honestly labeled as a guided demo).

7. **Light Mode Rendering & UI Visual Bugs Found in Inspection (`Partially working`)**:
   - Earlier visual screenshot inspection uncovered: (a) a full-screen `fixed inset-0` opaque overlay inside `FeaturePreviewsSection` covering the Hero until replaced with `<SectionAtmosphere>`, (b) mobile 390px badge overlap in `MoveStudioPage` / `KinematicHuman3D`, and (c) faint button/satellite text during Light Mode switch (`Navbar` `Sign In`, `HeroExperience` `See How It Works`, `WellnessCore3D` satellite pills) caused by theme color transition lag and utility overrides under rapid theme switching.
